# Synthetic BAM validation plan

## Testing principle

One simulator cannot answer every question. Directly constructed BAMs are the
right oracle for exact counting and CIGAR edge cases; transcript-derived FASTQ
simulation followed by alignment is the right test for realistic end-to-end
behaviour. Using only the latter would make expected BAM coordinates and counts
dependent on aligner heuristics, so failures would not localise to cortar.

Use three layers:

1. in-memory `GRanges` unit tests for event membership, labels and formulae;
2. tiny deterministic SAM/BAM fixtures for extraction and counting;
3. a smaller number of FASTQ-to-aligner integration datasets for biological
   realism.

Expected results must be written independently in a manifest, not generated by
calling cortar's own annotation or quantification functions.

## Recommended tools

### Deterministic fixtures: pysam plus samtools

[pysam](https://pysam.readthedocs.io/en/stable/usage.html) can create
`AlignedSegment` records with exact flags, positions, CIGAR strings, mate fields,
mapping qualities and tags. It is the preferred fixture generator because a
short script can express each read class and its ground truth.

[samtools](https://www.htslib.org/doc/samtools.html) should sort, index and
validate the result. At minimum, run `samtools quickcheck`, `samtools view` on
the target region and `samtools flagstat`. A plain-text SAM template converted
with `samtools view -b` is an equally good choice for a handful of records.

For a junction whose one-based inclusive intron coordinates are `[s, e]` and
anchor length is `a`, a simple single-end record can use:

```text
POS   = s - a
CIGAR = aM(e - s + 1)NaM
```

Use unique QNAMEs and a declared reference length large enough for every record.
Generate sequences and qualities of exactly the query-consuming CIGAR length.

### Transcript-derived reads: Polyester plus STAR

[Polyester](https://bioconductor.org/packages/release/bioc/html/polyester.html)
generates RNA-seq reads from supplied transcript FASTA or GTF plus genome FASTA,
with controlled transcript abundances and replicates. Create canonical and
engineered alternative transcripts, simulate FASTQ, align with the same pinned
STAR configuration used for production, then run cortar on the resulting BAMs.
This layer tests transcript structure, anchors, mapping ambiguity and aligner
interaction, but exact realised junction counts must be read from the BAM before
asserting cortar output.

### High-fidelity optional layer: BEERS2

[BEERS2](https://beers2.readthedocs.io/en/latest/) models library preparation
and sequencing biases and can emit FASTQ and SAM. Use it only after the small
deterministic suite is stable; its configuration and runtime make it poorly
suited to every pull request.

## Fixture design

Use a tiny synthetic annotation in helper-level tests. For full `cortar()` tests,
either add dependency injection for annotation/genome objects or place reads at
well-characterised coordinates of one small bundled transcript such as EMD.
Dependency injection is preferable because it avoids coupling tests to a large
human genome package and makes plus- and minus-strand toy genes easy to reason
about.

A useful toy plus-strand transcript has four exons and three introns with unique
lengths. Add a mirrored minus-strand gene on another contig. Choose canonical
GT-AG motifs and reserve nearby GT/AG coordinates for cryptic sites. Keep all
features far from contig ends.

Each fixture directory should contain:

```text
fixture-name/
  reads.bam
  reads.bam.bai
  expected-events.tsv
  manifest.yaml
```

The manifest should record reference checksum, coordinate convention, read
length, paired/stranded settings, every record class and expected inclusion or
exclusion. Commit the generator script and manifest; generated BAMs may also be
committed because they should be only kilobytes.

## Ground-truth event matrix

### A. BAM extraction and flag behaviour

| Case | Construct | Required assertion |
|---|---|---|
| Canonical SJ | `M-N-M` at one canonical intron | exact SJ coordinates and count |
| Two N operations | `M-N-M-N-M` | both junctions counted once per alignment |
| Anchor lengths 7, 8 and 9 | junction reads with short anchors | establish that SJ has no cortar anchor threshold |
| IR boundary 7 versus 8 bp overlap | ungapped reads at each boundary | only full eight-base overlap contributes |
| Asymmetric IR | 12 reads at start, 8 at end | `IR_count == 10` |
| Duplicate flag | identical primary records, one with 0x400 | duplicate excluded |
| Secondary flag | one record with 0x100 | secondary excluded |
| Supplementary flag | one record with 0x800 | capture current inclusion behaviour |
| MAPQ 0 versus high MAPQ | otherwise identical reads | both counted under current code |
| NH 1 versus NH 2 | primary alignments with tags | both counted under current code |
| Unmapped and out-of-range | flagged/positioned records | excluded by reader/range restriction |
| Paired mates share a junction | controlled mate CIGARs | establish whether score is alignment- or fragment-counted in this path |
| Orphan mate | paired flag with unmapped mate | establish `readGAlignmentPairs()` exclusion |
| Strand modes 0, 1 and 2 | reciprocal mate orientations | expected strand and event inclusion |

Do not encode uncertain paired-end expectations until the fixture has been
inspected independently with `junctions()`/`summarizeJunctions()` and the result
has been reviewed. The purpose of this test is to freeze an observed library
semantic that cortar currently delegates.

### B. Event assignment and annotation

| Case | Construct | Required assertion |
|---|---|---|
| Canonical plus and minus | exact selected intron | canonical label on both strands |
| Cryptic donor | one canonical boundary, one novel boundary | correct strand-specific donor label |
| Cryptic acceptor | reciprocal construction | correct strand-specific acceptor label |
| Unknown strand | non-natural motif or `*` SJ input | `cryptic (strand unknown)` |
| Single-exon skip | intron 1 start to intron 2 end | skip label; row emitted for both boundary introns |
| Multi-exon skip, `ria = FALSE` | intron 1 start to intron 3 end | emitted for first and last introns only |
| Multi-exon skip, `ria = TRUE` | same junction | also emitted for every fully spanned internal intron |
| Alternative transcript | exact non-selected-transcript intron | `annotated == "alternative"` unless canonical overrides |
| Canonical/alternative collision | exact intron in both sets | canonical override |
| Fully novel SJ | no selected boundary | absent unless it enters a pool through the RIA containment rule |
| Shared boundary | two introns share start or end | freeze or reject ambiguous metadata assignment |
| Overlapping opposite-strand genes | same coordinates | verify strand-aware separation |

### C. Quantification

| Case | Counts | Required assertion |
|---|---|---|
| Canonical only | SJ 100, IR 0 | proportions 1 and 0 |
| Mixed SJ | canonical 80, cryptic 20, IR 0 | 0.8 and 0.2 |
| Mixed SJ and IR | canonical 80, cryptic 20, IR sides 12/8 | 80/110, 20/110 and 10/110 |
| Zero coverage | every count 0 | every proportion 0, not `NA` |
| Event absent in one sample | event appears only in another sample | union row exists with zero count |
| Repeated skip | same skip in several intron pools | separate denominator and expected percentage per intron |
| Fractional IR | odd total boundary count | half-count preserved in raw and denominator |
| Compositional response | hold canonical count fixed, add cryptic reads | canonical proportion falls exactly as formula predicts |

For every positive-coverage sample/intron group, assert that proportions sum to
one within a tight tolerance. Also assert that no cross-intron sum is presented
as meaningful.

### D. Default and panel comparison logic

| Case | Required assertion |
|---|---|
| Same family | excluded from controls and included in family columns |
| Same gene, different family, default mode | excluded from controls |
| Same gene, different family, panel mode | included in controls |
| Unrelated `sampletype == test` row | currently included as a control |
| Coverage below, equal to and above threshold | only strictly above retained |
| `het`, `hom`, `hemi`, blank and numeric threshold | exact mapping to 60, 30, 30, 0 and numeric |
| No controls | mean/SD `NA`, `controln == 0` |
| One control | mean defined, SD `NA` |
| Identical controls | SD zero; any non-zero difference sets all SD flags |
| Known three-control vector | independently calculate mean and sample SD |
| Family-only event | exact `unique` numerator/denominator, including proband |
| Missing percentage | verify current NA propagation |

### E. Research mode

Use two samples with deliberately unequal depths but known proportions. Assert
that `controlavg` is the unweighted mean of sample proportions rather than the
pooled-count proportion. Also test one sample, zero coverage, relatives, missing
values, output sorting and the removal of individual sample columns.

### F. Input and failure cases

Add explicit regression tests for every issue in the defect register:

- transcript column currently ignored;
- ambiguous canonical or unversioned transcript selection;
- invalid and punctuation-containing gene identifiers;
- assembly/annotation compatibility;
- invalid `input_type`;
- missing columns and duplicate sample IDs;
- SJ mode without a real BAM path;
- empty BAM/SJ/IR input;
- debug output path and undefined object;
- missing or duplicated IR boundary rows;
- chromosome naming mismatch and wrong strandedness.

Tests for defects should initially capture the current failure with
`expect_error()` or be marked as an explicit expected failure in the issue
tracker. When fixed, replace them with the desired behavioural assertion.

## Independent expected-value example

For a test sample and three controls at one event:

```text
test proportions     = 0.70
control proportions  = 0.20, 0.40, 0.60
control mean         = 0.40
sample SD            = 0.20
difference           = 0.30
two_sd               = FALSE because 0.30 is not greater than 0.40
```

Keep this arithmetic in a literal expected-values file. Do not calculate it by
calling `compareSplicing()` or reusing its helper code.

## CI acceptance criteria

1. Pin R, Bioconductor, pysam, samtools and STAR versions.
2. Regenerate fixtures in a separate CI job and compare SHA-256 checksums.
3. Run `samtools quickcheck` on every BAM and require an index.
4. Assert raw counts before percentages, annotations before comparisons, and
   comparisons before report formatting.
5. Compare tables by typed keys and numeric tolerance, not entire formatted
   workbooks alone.
6. Retain one golden end-to-end report, but make focused ground-truth tests the
   primary correctness evidence.
7. Record the audited cortar commit and bundled annotation checksum in each
   golden manifest.

## Implementation order

1. Add in-memory event-pool and percentage tests.
2. Add a pysam/samtools single-end fixture generator and cases A–C.
3. Add default, panel and research arithmetic fixtures.
4. Fix input validation and transcript-selection defects with regression tests.
5. Add paired/strand BAMs.
6. Add one Polyester → STAR → cortar integration scenario.
7. Add BEERS2 only if realistic library bias is a validation requirement.
